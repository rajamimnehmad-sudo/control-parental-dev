# Glosh Remote Spike

`REMOTE-INSTALL-CONNECTION-00`

Standalone laboratory project for proving remote technical access to an **already-used Android phone, without a PC on the client side**.

This project is deliberately isolated under `tools/` so it does not modify App Usuario, App Admin, Chrome/GloshIA, root Gradle settings, or production backend code.

## Goal of this spike

PASS requires all of the following on Android 11+:

1. User installs this temporary APK.
2. User enables Wireless debugging and opens **Pair device with pairing code**.
3. The APK pairs with the ADB daemon of the **same phone**.
4. The APK opens a WSS connection outward to a temporary relay running on the technician Mac.
5. Mac and Android mutually authenticate with a one-time 256-bit key.
6. Mac executes only allowlisted diagnostic actions (`ping`, `whoami`, `device`, `owners`, `users`, `battery`).
7. Android returns the results encrypted end-to-end.
8. Closing/revoking the session prevents further remote commands.

No Device Owner change is made in this ticket. The next pilot may use the proven channel to prepare and install Glosh adaptively.

## Why the lab relay is not Supabase yet

For the first physical proof we want to test the hard part — local ADB pairing plus remote control — without adding a persistent backend. The Mac relay binds only to localhost and `cloudflared` creates an outbound-only **Quick Tunnel** with a random HTTPS/WSS URL.

If the spike passes, the Quick Tunnel is replaceable by Glosh-owned infrastructure without changing the Android ADB layer or the encrypted command protocol.

## Build

This is a standalone Gradle build. From repository root:

```bash
./gradlew -p tools/glosh-remote-spike :app:testDebugUnitTest :app:assembleDebug
```

Expected APK:

```text
tools/glosh-remote-spike/app/build/outputs/apk/debug/app-debug.apk
```

Requirements for the first real build/gate are intentionally deferred to Codex on the Mac because they require Android SDK/JitPack resolution and a physical Android device.

## Mac relay

Create a virtual environment:

```bash
cd tools/glosh-remote-spike/mac
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The physical test also needs the `cloudflared` executable available on the Mac. Then:

```bash
python glosh_remote_relay.py
```

The tool starts a localhost WebSocket server, starts a Cloudflare Quick Tunnel, and prints a one-time URI such as:

```text
gloshremote://join?v=1&url=wss%3A%2F%2F...&sid=...&k=...
```

Paste that URI into the APK after local ADB pairing succeeds.

On the Mac, the available commands are:

```text
ping
whoami
device
owners
users
battery
status
help
quit
```

There is intentionally **no arbitrary shell** in this version.

## Android steps for the lab gate

1. Install the APK.
2. Open **Developer options** from the app.
3. Enable **Wireless debugging**.
4. Tap **Pair device with pairing code**.
5. Remember the six-digit code and return to Glosh Remote Spike while the pairing screen is still active.
6. Enter the code and tap **Pair local ADB**.
7. Wait for the app to show the `id` canary.
8. Paste the join URI generated by the Mac relay.
9. Tap **Connect to Mac**.
10. Run the allowlisted commands from the Mac.
11. Close the session and verify new commands fail.
12. Revoke the temporary ADB identity and turn Wireless debugging off.

## Security properties of the spike

- ADB is local to the phone; port 5555 is never exposed publicly.
- Mac and phone can be on completely different networks.
- Cloudflare only transports the WSS connection; command/result payloads are additionally AES-256-GCM encrypted end-to-end.
- Session key is random, 256-bit, memory-only on Android and expires with the lab session.
- Mutual HMAC challenge/response prevents accepting a relay that does not know the one-time key.
- Monotonic per-direction sequence numbers reject replayed encrypted frames.
- Android maps remote action names to a fixed local allowlist; remote input cannot contain raw shell commands.
- Output is capped to 64 KiB per action.
- Resetting the temporary ADB identity deletes the app-private private key/certificate.

## Known limitations / next gates

- Android 11+ only for this spike.
- Wireless debugging remains enabled during v0. A later bridge can investigate starting a shell-side service and disabling Wireless debugging after bootstrap.
- Session is not designed to survive reboot.
- Some OEMs may alter Developer options or mDNS behavior; pilots will document recipes by manufacturer/model.
- Android 17 local-network permission behavior is not part of this first target (`targetSdk 35`); it must be addressed before raising target to API 37.
- Quick Tunnels are for development/testing only and must not become the production Glosh relay.
- The libadb dependency itself states it has not undergone a security audit. This spike limits its role to localhost ADB bootstrap and does not expose its API over the network.
